## Durable Design Decisions

- Paper first, live only after evidence.
- Broker state is source of truth; startup reconciliation is mandatory.
- Strategies are pure signal generators; execution and risk live outside strategies.
- Single-leg trades pass through `RiskManager.evaluate`; defined-risk MLEG spreads use strategy max-loss sizing plus sleeve gates.
- Exits are never blocked by edge filters, regime gates, or sleeve capacity.
- Mandatory macro SMA entry gates fail closed when history is insufficient;
  an unavailable indicator must never silently weaken an entry policy.
- New filters should return `EdgeFilterDecision`, not only boolean Series.
- Options and spreads must use broker-supported Alpaca SDK paths; avoid home-grown execution behavior when the SDK provides a native route.
- Slippage metrics must separate execution quality, implementation shortfall, and stop-gap erosion; no operator-facing slippage number should exist without an explicit stored benchmark contract. See `docs/slippage_unification_design.md`.
- Realized P&L and restart state use broker fill cost basis, never the strategy's decision/reference price; reference prices remain execution-quality and signal-analysis metadata.
- Every number on an operator-facing report must have a live source, and a report field whose only source is a default is a defect, not a placeholder. The daily P&L report shipped `Unrealized P&L` and `Max intraday drawdown` at a hardcoded `$0.00` across all 71 reports written before 2026-08-19, because both were keyword arguments defaulting to `0.0` that the sole production caller never passed. Realized P&L comes from the trade log, unrealized from the broker snapshot's open positions (`unrealized_pnl_from_positions`), and intraday drawdown from the engine's equity path (`TradingEngine.max_intraday_drawdown`), which observes every broker snapshot including the shutdown one the report is built from, and persists the day's peak to `data/equity_path_state.json` so a `recycle_bot.sh` mid-session does not restart the metric at zero and let the second session's shutdown overwrite the day's report with only the post-restart decline. Downtime is covered by reconciling against the broker's own 1-minute intraday equity series (`AlpacaBroker.get_intraday_equity_path` → Alpaca `get_portfolio_history`) at shutdown, scoped to an explicit UTC-day window because Alpaca's `period="1D"` is a rolling 24h window ending now (verified 2026-08-19: it spanned 08-18T17:17Z→08-19T17:17Z) and `intraday_reporting="continuous"` so overnight counts. Broker and locally-observed figures are combined with `max`, never replaced — the broker series is finer-grained and more complete, but a trough between its minute marks that this process directly observed must not be reported as smaller, and `max` makes an API failure degrade to the local number instead of losing it. Drawdown is running-peak, not `max - min`: on 2026-08-19 the true figure was $577.88 while the range was $787.13, a drop that never happened because the low preceded the high; a unit test on the reporting module cannot catch a caller that never calls, so the call site itself is pinned by AST guards in `tests/test_daily_report_wiring.py`. The weekly report was never contaminated by those zeros — it reads nothing from the daily markdown files but their existence and their paths — but it carried no P&L figure of any kind for the same underlying reason, having been written before `realized_pnl` was a column on `trades`; it now reads realized P&L and per-strategy attribution through the same `read_realized_pnl_events_in_range` query the daily report uses, with a test asserting the weekly total equals the sum of its own dailies.
- Per-strategy stop-risk targets size equity entries (`STRATEGY_RISK_PER_TRADE_PCT`, 11.48). Decision budget, approved risk, binding cap, and launch multiplier are stored before submission; fill-time risk is separate. Recheck target coverage when watchlists change.
- Do not add a second same-underlying single-leg options strategy until the ownership model supports it.
- Do not tune paper-watch parameters pre-emptively; audit first, change second.
- `position_uid` is project-wide lifecycle identity — generated by `engine.lifecycle.new_position_uid()` before broker submission, persisted in the `position_lifecycle` table. Phase A wires it through the operator CLI only; other subsystems (health monitor, allocator, reconcile, alerts, dashboard) integrate later, each in its own PR, per `docs/operator_controls_proposal.md` §17.
